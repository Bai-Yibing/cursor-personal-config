# 端侧推理加速与质量改进

前置：先有 `edge-accel-eval` 的段表、质量表和三轴归因。没有报告就先评，禁止凭「核没吃满」直接改模型。
本 skill 回答：**评完之后动哪一层、按什么顺序、质量和速度如何分开验收**。适用于检测、分割、立体、语音、语言模型前端等所有加速器静态图/分段图。

## 1. 问题定义

评测之后的典型失败：

- 瓶颈在搬数，却去加核、改量化配方
- 质量和速度绑在同一个包上左右互撕
- 同时改骨干、iters、runtime、分辨率，无法归因
- 把主机 JPEG/HTTP 税当成芯片算力不足
- 用校准余弦当「改完变好了」

需要一套 **按瓶颈选层** 的加速框架，而不是一张万能调参表。

## 2. 不变量 / 第一性原理

1. **一次只动一个主杠杆**，其余锁定；每刀都要速度段表 + 任务质量双门。
2. **先便宜后昂贵**：runtime/系统 → 调度/核数 → 图与算子 → 算法 iters/ROI → 改骨干/蒸馏 → 再考虑 QAT 或换位宽。
3. **速度 SKU 与质量 SKU 可以不是同一个包**。默认直播走速度包；评测/近距/开放域走质量包。
4. **不为提速破坏全加速器门禁**。打回 CPU/hybrid 的「更快图」通常更慢且不可控（见 `horizon-bpu-ptq`）。
5. **量化配方默认冻结**。提速不靠乱改 kl/敏感层 fp16；提质量先校准域和任务数据，再考虑 QAT。
6. **能并行才谈并行**。串行段、多包 IOVA、单会话禁双持有时，不要设计「两段同时占核」。
7. **任务指标过了才算质量提升**；墙钟过了才算速度提升。余弦、编译器 FPS、平均 ratio 都是线索。

## 3. 推理加速框架（层）

从上到下，越往下越贵、越容易伤质量。

```text
L0 系统 I/O     相机/文件 → 预处理 → 提交 → 后处理 → 显示/控制
L1 运行时       常驻、缓存、输入是否每轮从 DDR 提交、绑核、独占、堆
L2 调度/映射    core_num、切分轴、tile、SRAM、多段调用序
L3 图与算子     融合、等价改写、禁止落 CPU 的算子、静态边界
L4 算法         迭代次数、ROI、时序复用、级联/早停、输入分辨率
L5 模型结构     骨干宽度/深度、蒸馏、剪枝、多尺度头
L6 训练/量化    校准域、QAT、位宽、蒸馏教师
```

评测报告把墙钟标到某一层后，**只在该层选刀**。

### 3.1 按瓶颈选层（决策树）

```text
eval 主因是什么？
  ├─ 主机税（服务 e2e ≫ 纯 run）
  │     → L0：共享内存/原始张量，去掉编码往返；预处理与推理解耦
  ├─ 迭代体墙钟随 N 线性、且与核数无关
  │     → L1 常驻大张量 / 少提交；不行再 L4 降 N（质量门）
  ├─ 重段随核数亚线性、编译估计≪板端
  │     → L1 提交税；L2 只给该段升核（已升则停）；L3/L5 减激活与权重
  ├─ 轻段升核零收益
  │     → 保持单核；不要全段多核
  ├─ 利用率低 + 权重大 / 激活大
  │     → 带宽墙：L3 融合减少写回；L5 瘦骨干；不是加核
  ├─ 任务指标差、速度已够
  │     → L6 校准域/QAT；L4 加 iters 或分辨率；L5 加容量
  ├─ 速度与质量同时要
  │     → 双 SKU，禁止一个包两头拉满
  └─ 多段想重叠
        → 先查 IOVA：兄弟段同会话通常不能两进程双持有
```

### 3.2 各层杠杆（速度）

| 层 | 做法 | 何时 | 风险 |
|----|------|------|------|
| L0 | 原始帧/共享缓冲；后处理异步；控制面与数据面分离 | 服务路径明显慢于纯推理 | 不同步、掉帧需单独测 |
| L1 | 常驻权重；关跨帧泄漏的缓存；大中间量只提交一次；绑核=编译核；独占频率 | eval 已证提交/泄漏 | 常驻吃堆；关缓存可能 +数个百分点拷贝 |
| L2 | 只给算力墙段 `core_num>1`；切分轴要能链上且量化不崩 | 段表证明该段算力墙 | Recv/同步；轻段升核浪费 ION |
| L3 | 算子融合；Scatter/Resize/Transpose 改写驻加速器；tile pack 进 batch | 图内 sync 多或 CPU fallback | 必须 float 等价（cosine/maxabs 门）再编 |
| L4 | 降迭代、ROI、上一帧作初值、降输入分辨率、级联小模型 | 迭代线性或分辨率平方涨 | **质量门**；几何任务先算 mm/px 预算 |
| L5 | 更窄更深或反过来按剖面；蒸馏到学生；结构化稀疏若硬件真加速 | 重段仍是墙且 L2 已挖尽 | 重训/重编；学生必须过任务指标 |
| L6 | 更低位宽仅当任务指标过；QAT 保精度以便用更小学生 | 质量卡住或 int 掉点 | 配方门禁；禁止为速度乱 fp16 头 |

### 3.3 各层杠杆（质量）

| 层 | 做法 | 何时 | 不要 |
|----|------|------|------|
| L0 | 标定、曝光、同步、预处理与训练一致 | 相机域指标差 | 用错输入域刷余弦 |
| L4 | 增加 refinement / 更大 ROI / 更高分辨率 | 速度预算还剩 | 无限加 iters 当免费精度 |
| L5 | 更大骨干、更好预训练、任务头 | 容量不够 | 只加宽不测延迟 |
| L6 | 校准对齐部署域；calib≠held-out；敏感层白名单；QAT | PTQ 触顶 | 同矩阵重编刷余弦 |

质量变好的验收永远是 **held-out 任务指标**，不是训练 loss 或单节点 cosine。

### 3.4 算子与图

- 加速器只吃它支持的密集计算。不支持的算子优先 **改写**，不要指望它「在 CPU 上也能跑就行」。
- 融合减少中间写 DDR，既提速也可能略改数值 → float 对齐后再 PTQ。
- 动态 shape / 控制流：从在线调用图切静态段，缓存可复用的编码。
- 大二维注意力、超长无 past 预填：先缩窗口或切段，禁止同图硬撞编译器上限。

### 3.5 硬件与调度

- **Roofline**：先判断这段是 MAC 满还是 DRAM 满。DRAM 满则加核≈抢同一条总线。
- **堆**：权重堆、激活堆、相机 ION 分列；常驻四段之前先算峰值之和。
- **频率与争用**：未独占时不谈芯片时延。
- **多核**：划分不是复制；核间通信计入延迟；绑定少于编译核会失败，多于不会自动再切分。
- **流水重叠**：仅当运行时契约允许两段真正并发且 IOVA 已板上验证。默认假设 **一段在飞、其余在等**。

### 3.6 算法与模型设计（部署导向）

设计阶段就为端侧留预算，而不是训完再求编译器救命：

- 输入分辨率、refinement 次数、是否时序递推，写成 **可开关超参**，方便 L4 扫描。
- 重计算与重访存分开：骨干可多核；体积/迭代体先按带宽设计。
- 质量关键放在小头或少次迭代能挽回的地方，避免「精度全靠最后八次大核循环」。
- 学生网以教师任务指标为门，不以教师余弦为门。

## 4. SOP（评完之后）

1. 打开 eval 报告，圈 **一个** 主因层（L0–L6）。
2. 写可否证假设：「只改 X，墙钟降 ≥a 或指标升 ≥b，其它段不变」。
3. 选对照：未改包 + 只改 X 的包/配置。
4. 实现最小 diff；重编则独立 workdir，不覆盖已验收 latest。
5. 再跑 `edge-accel-eval` 的最小集：该段墙钟 + 任务指标 + 堆是否恶化。
6. 过门 → 记 SKU（速度默认 / 质量默认）。不过 → 回滚，换下一层，禁止叠加上一刀的残补丁。
7. 更新 investigation 与 `PROJECT_STATE.md`。

建议扫描顺序（速度）：L0/L1 一天内能证伪 → L2 已有多核包对照 → L4 iters/分辨率曲线 → L3/L5 才开新编译。

## 5. 度量与门禁

| 虚荣 | 验收 |
|------|------|
| 「感觉能到 5 FPS」 | 独占纯推理 e2e 分位（p50/p95） |
| 学生网 cosine 高 | 与教师 **同一 held-out 任务指标** |
| 降 iters 墙钟好看 | 任务指标仍过产品阈值 |
| 新骨干 MAC 更少 | 板端该段墙钟真降，且无 CPU 回落 |
| 升核 ratio 更高 | 端到端下降；ION 可常驻 |

双门：**速度门**（段 + e2e）与 **质量门**（任务多指标）都写进假设，缺一则该刀无效。

## 6. 故障分类

| 症状 | 原因 | 否证 |
|------|------|------|
| 改 runtime 无收益 | 主因不在 L1 | 对照纯 run vs 服务 e2e |
| 降 iters 质量崩 | 精度预算在迭代体上 | 画指标–N 曲线，取拐点 |
| 瘦骨干速度几乎不变 | 仍是搬数墙或主机税 | 再看段表 |
| 融合后任务掉点 | 数值不等价 | 回 float maxabs/cosine 门 |
| 想两段并行就 IOVA | 同会话双持有 | 单进程串行或冷启换管线 |
| QAT 很慢才略好 | 域或结构才是真因 | 先校准域 A/B |

## 7. 反模式

| 本能 | 为何失败 | 正确做法 |
|------|----------|----------|
| 评完立刻改骨干 | 可能 L0/L1 就能省一半等待 | 按层由便宜到贵 |
| 一个包既要最快又要最好 | 帕累托面上是两点 | 双 SKU |
| 为提速改量化白名单 | 常落 CPU 或毁头 | 冻结配方 |
| 无假设连改三处 | 无法归因 | 一刀一报告 |
| 并行段「应该能重叠」 | IOVA/会话契约不允许 | 先验证方向再设计 |
| 用教师余弦收学生 | 任务仍可能差 | 任务指标门 |

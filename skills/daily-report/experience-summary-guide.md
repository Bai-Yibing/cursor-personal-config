# 每日经验总结写法指南

## 核心原则（必读）

**日报写给领导，经验写给自己——两类文档，不可混写、不可互相替代。**

| | 日报 | 每日经验总结 |
|---|------|----------------|
| **读者** | 领导 | **自己**（三个月后的你；离线翻阅） |
| **目的** | 汇报进展与判断 | **可复现的实验记录** + **可迁移的结论** |
| **详细程度** | 适度，一页为佳 | **为何 / 改了什么代码 / 怎么跑 / 原始日志 / 普适结论** |
| **数据** | 关键数字 | **表内数字 + 摘自日志/json 的原文字段** |
| **经验** | 点到为止 | **预期是否被打脸** + 无效尝试 + 可复用主张 |
| **结论** | 工程判断一句话 | **有边界的普适结论**（不是待办清单） |

### 零号门禁：离线可复现（最高优先级）

借鉴 research log / 实验笔记本 / Evergreen：

> **三个月后断网、只读这一篇——能否说出：为何这么改、改了哪几段代码/配置、用哪条命令跑、日志里出现过什么关键数字、普适结论在什么条件下成立？**

答「不能」→ 继续往正文补 **假设与预期、diff、命令+原始输出**；禁止用「见某某路径 / 见 COMMANDS.sh」搪塞。

| 合格 | 不合格（常见翻车） |
|------|-------------------|
| 每个关键决策写清 **假设 + 预期数字/现象** | 只有事后结论，像压缩日报 |
| 关键改动有 **unified diff 或改前/改后代码块** | 「改了评测脚本支持 roi_half」无 hunk |
| 完整可复制命令 + **stdout/stderr 或 summary.json 字段原文** | 只写 `bash COMMANDS.sh` |
| 指标表旁注字段出处（如 `roi_1m_MAE_mm`） | 「结果见 output 目录」 |
| 文末 **普适结论**（主张 + 边界 + 置信度） | 材料索引 / 路径目录 / 领导待办表冒充结论 |

### 禁止索引式写法

经验总结**不是目录**。禁止：

- 「材料索引」专节、路径大表冒充正文
- 「补充验证数据 / 自远端嵌入 / 自动收集」附录 dump
- **要求**另产 `YYYYMMDD.md` 短索引（文件夹导航用的 `每日清单.md` 除外，且不属于经验写作）
- 用「目录」代替论证；用待办表代替普适结论

### 远端补充硬禁令

拉到材料后必须改写对应实验环 / 代码节 / 结果节。禁止文末整文件挂载；禁止另建审计旁路 md；禁止整贴无关 README/INSTALL。

## 强制：每个方法一张「方法卡」（最高优先级写作单元）

**经验正文的主体是方法，不是指令清单。** 每个关键方法（几何改法、评测口径、选型规则、封板收敛……）必须按四段写满：

| 段 | 必须写什么 | 禁止 |
|----|------------|------|
| **背景** | 当时面对什么现象/约束/已有基线 | 空泛「需要优化」 |
| **原因** | 为何选这个方法、不选什么、物理/工程直觉 | 只写「按用户要求」 |
| **方法** | **完整可运行的改前代码 + 改后代码**（或 unified diff）；关键参数/公式；验证步骤可附命令但命令不能替代代码 | 只有 `bash xxx.sh`；代码用 `...` 省略到看不懂 |
| **参考** | 依据来自哪：论文/官方文档/前日经验/COMPARE 字段/对话结论；并写清「本方法边界」 | 无出处的断言 |

命令与日志属于方法卡里的「验证」子节，用来证明方法生效；**不能**用命令列表冒充「说明了怎么改」。

方法卡写完后，再用实验环串时间线（假设→预期→Result→信念更新）。

## 强制：五段实验环

每个关键决策至少写完一轮（挂在对应方法卡之后或之中）：

1. **假设**：当时相信什么  
2. **预期**：具体数字或可观测现象（写下来才能被打脸）  
3. **Setup**：主机角色、环境键、完整命令  
4. **Result**：原始输出摘录（日志 5–30 行或 json 关键字段），先不要解释  
5. **更新后的信念**：假设存活 / 削弱 / 推翻；下一步依据是什么  

参考：[The research log](https://fabric.so/blog/the-research-log)。

## 推荐结构（长文模板）

```text
# YYYY-MM-DD 经验总结：<主题>

> 主机角色 / 时间 / 自包含声明

## 1. 总问题与主指标（全局背景）

## 2. 方法卡（正文主体；每张卡：背景→原因→方法含改前改后代码→参考）
### 方法 1：…
### 方法 2：…

## 3. 实验时间线（各方法验证的假设/预期/原始结果/信念更新）

## 4. 结果总表（数字旁注 json/日志字段）

## 5. 误判与否证

## 6. 普适结论（可迁移主张 + 边界）

## 7. 仍未知
```

## 写作硬标准

### 1. 代码必须可核对（方法卡的「方法」段）

- 每个关键方法：先给 **改前** 完整片段，再给 **改后** 完整片段（或等价 diff）；读者应能看懂改了哪几行逻辑。  
- 禁止只有 shell 指令而无 Python/C++/配置 hunk。  
- 配置键：改前/改后并列。

### 2. 结果必须落日志

- 指标表里的关键数字，正文某处能找到对应原始字段摘录。  
- 异常/离群（如全图 depth MAE 被炸）必须写进 Result，并说明为何不进主结论。

### 3. 预期必须先于解释

- 禁止只写「结果很好所以方法对」；必须能对照「当时预期是什么」。

### 4. 普适结论必须严谨

每条结论至少写清五件事，禁止口号式单行：

1. **主张**（一句话）  
2. **成立前提 / 约束条件**（协议、主指标、同变量控制）  
3. **本轮证据指针**（表或字段）  
4. **不适用 / 失效条件**  
5. **置信度**（且只在约束内）

缺前提的「普适」一律视为不合格。

### 5. 标题不加括号注释

Markdown 标题（`#`–`####`）只写短名；补充说明放到标题下正文。禁止 `### 方法 1：xxx（中心半幅 crop → letterbox）` 这类括号堆砌。

### 6. 文风：实验笔记，不是审查报告

写给三个月后的自己，用完整、好读的句子；严谨靠约束写清，不靠套话。

| 宜 | 忌 |
|----|----|
| 「当天要回答两件不同的事」 | 「若拆不开，封板叙事三个月后无法审计」 |
| 「当前部署配置下的近距误差」 | 「产品部署数 / 模型能力数」这类生造词 |
| 「适用 / 不适用」 | 堆「成立边界 / 失效边界 / 计量前提」标签当正文 |
| 「证伪 / 判断更新」 | 满页加粗、箭头公式腔、O-H-V-C 口号而不解释 |
| 少用「必须 / 禁止」叠句；改成「…才…」「…否则…」 | 审查腔、翻译腔、表格填空腔冒充论证 |

结构仍要完整（方法卡、实验环、结论五要素）；**读起来应像笔记，不像制度条文**。

### 7. 数据不编造

- 没有的数字写「待补」+ 补什么、从哪台主机拿。  
- 未跑同几何对比就不得宣称「超过公版」。

### 8. 全库/批量改造时的分档

| 档 | 怎么写 |
|----|--------|
| 证据充足 | 按样板深改到方法卡 + 实验环 + 结论五要素 |
| 证据不足 | 六段骨架仍要；深度按材料上限；缺代码写待补 |
| 空档日 | 诚实占位，不伪造方法卡 |
| `YYYYMMDD.md` | 仅导航占位，不升格为经验正文 |

### 9. 中文写入（Windows）

统一遵循 skill / rule **`utf8-chinese-docs`**（通道选择、校验脚本、`\n` 转义陷阱）。经验文与 skills 同样适用；写完未过检不得交付。

## 取材清单

1. 本机 transcripts / terminals（关键输出贴进 Result）  
2. 改动机器上的 `git diff` / 文件前后（贴进「代码与配置改动」）  
3. 远端评测 `summary.json`、COMPARE、infer/eval 日志关键段  
4. 用户口述的目视现象（写入 Result，标注 `[用户口述]`）  
5. 日报仅对齐主题——**经验禁止写成日报加长版**

## 保存路径

| 文件 | 远端暂存 | 本机权威 |
|------|----------|----------|
| 长文经验总结 | `<项目根>/.cursor/工作存档/知识库/每日经验/YYYY-MM-DD-<主题>经验总结.md` | `D:\Documents\知识库\每日经验\` |
| 日报 | `.../工作汇报/日报/` | `D:\Documents\工作汇报\日报\` |

文件夹导航：`知识库/索引/每日清单.md`（一行一条；**不是**经验正文的一部分）。

**不产出**：周报、每周汇总、经验文内材料索引、`YYYYMMDD.md` 短索引（历史短索引可留档，新写不再要求）。

**不单独建目录**：评测报告、复现包说明等一律嵌入当日经验长文。

## 交付前自检

- [ ] 零号门禁：为何 / 改了什么代码 / 怎么跑 / 原始数字 / 普适结论 五件套齐全  
- [ ] 至少一轮完整五段实验环（含**预期**）  
- [ ] 关键改动有 diff；关键指标有日志/json 字段摘录  
- [ ] 无材料索引节；无 dump 附录；无领导待办冒充结论  
- [ ] 误判/否证已写；主指标书面定义已写  
- [ ] 篇幅与深度明显高于日报；隐私无真实 IP/凭据  

## 方法来源（借鉴，非教条）

- Research log：预期写下来，才能对抗事后合理化。  
- Lab notebook：外人只凭记录能重复实验。  
- Evergreen notes：文末主张可复访、可 refinement。  
- ADR：重要选择写清 Context / Decision / Consequences / 弃选理由。

落到本仓库的可执行规则：**路径不能替证据；摘要不能替实验；待办不能替结论。**

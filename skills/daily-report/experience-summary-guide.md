# 每日经验总结写法指南

## 核心原则（必读）

**日报写给领导，经验写给自己——两类文档，不可混写、不可互相替代。**

| | 日报 | 每日经验总结 |
|---|------|----------------|
| **读者** | 领导 | **自己**（三个月后的你；离线翻阅） |
| **目的** | 汇报进展与判断 | **单日完整知识链路**：当天判断可还原、关键步骤可复现 |
| **详细程度** | 适度，一页为佳 | **自包含优先**：正文即证据，路径只是附录 |
| **数据** | 关键数字 | **表内即数字**：多轮对比、时间戳、指标出处 |
| **经验** | 点到为止 | **可复用方法** + 无效尝试 + 误判纠正 |
| **结论** | 工程判断一句话 | **证据链闭合**、置信度、未验证不装定论 |

### 零号门禁：离线自包含（最高优先级）

借鉴 Evergreen / 实验笔记本 / ADR 的共同要求：**写给未来的自己，不假设你还记得上下文，也不假设你还能打开原始日志机。**

自问（交付前必答）：

> **断网、不打开其他文件、不 SSH，只读这一篇经验总结——能否重建当天的完整知识链路（现象→假设→验证→改动→数据→结论）？**

答「不能」→ 继续往正文里**嵌入**证据，禁止用「见某某路径」搪塞。

| 合格 | 不合格（常见翻车） |
|------|-------------------|
| 关键日志 **原文摘录**（5–30 行） | 只写 `见 /var/log/xxx.log` |
| 关键 diff **改前/改后代码块** | 只写 `改了 foo.cpp` 或 commit hash |
| 关键脚本 **核心逻辑/命令 + 期望输出** | 只写 `scripts/run.sh` |
| 指标 **表内写全**（主机、轮次、数值） | 「结果见 output 目录」 |
| 配置/参数 **键值写进正文** | 「用的是默认 yaml」 |

路径、transcript id、bag/地图目录可以写在「材料索引」——那是**定位原件**用的，**不能替代正文证据**。

体积权衡：二进制、整包 bag、超长日志不要整份粘贴；但必须留下**能独立支撑结论的最小充分摘录**（关键报错段、对比数字、diff hunk）。

## 与日报的区别

| 维度 | 日报 | 每日经验总结 |
|------|------|----------------|
| 读者 | 领导 | 自己（离线） |
| 文风 | 白话因果 | 结构化、可逐条核对 |
| 证据 | 代表数字即可 | **嵌入摘录** + 全轮次表 |
| 代码 | 不写 | **改前改后贴出**（非仅路径） |
| 结论 | 「今日总结」里带过 | 独立「完整结论」节 |
| 失败/误判 | 「存在问题」 | **正文必写**怎么误判、靠什么纠正 |
| 周报 | — | **不产出周报/周汇总**（已取消） |

## 推荐结构（长文模板）

```text
# YYYY-MM-DD 经验总结：<主题>

> 材料来源（transcript/终端/主机角色）| 修订时间
> 自包含声明：关键证据已嵌入正文；路径仅附录

## 0. 一句话结论（置信度：高/中/低）

## 1. 背景与现象
   表：任务、场地/版本、现象、影响（可观测、能量化）

## 2. 全天/多轮数据总表
   列：轮次、主机、时长、核心指标、是否达标、备注
   （数字写在表里，不写「见某 csv」）

## 3. 推理链（按事件拆，O→H→V→C）
   每步旁注：嵌入的日志摘录 / 命令输出 / 指标

## 4. 修复与改动清单
   表：对象、改前、改后、验证状态
   每个关键改动附 **diff 代码块**（或等价前后片段）

## 5. 命令与复现备忘（可复制）
   完整命令 + 在哪台主机执行 + 期望输出摘要

## 6. 独立 bug / 旁路问题

## 7. 可复用排查模板（编号步骤，步骤内含判据）

## 8. 完整结论（编号；判断 + 嵌入依据 + 置信度）

## 9. 后续行动（优先级）

## 10. 材料索引（可选定位原件：路径、transcript、commit）
   ← 仅附录；缺嵌入则本节约等于没写
```

另建短索引 `YYYYMMDD.md`（5–15 行）：主题、核心数据摘要、结论一句、链到长文。短索引**不可替代**长文。

## 写作硬标准（五条）

### 1. 自包含嵌入（相对路径优先）

对每个支撑结论的材料，按类型嵌入：

| 类型 | 必须嵌入什么 | 上限建议 |
|------|----------------|----------|
| 日志 | 含时间戳的关键段原文 | 每处 5–30 行 |
| 代码修改 | unified diff 或改前/改后对照 | 每个关键文件 1 个 hunk |
| 脚本/命令 | 可复制命令 + 关键 stdout/stderr 摘要 | 能复现关键一步即可 |
| 指标 | Markdown 表（含主机列） | 当日相关轮次尽量全 |
| 配置 | 关键键值（改前/改后） | 只写动过的键 |
| 决策（类 ADR） | 背景约束 → 选择 → 后果/弃选理由 | 一段即可 |

禁止句式：「详情见 xxx」「日志在 xxx」「脚本在 xxx」——除非正文已有充分摘录，路径仅作附录。

### 2. 足够详细

- 重大判断：时间 + 嵌入证据 + 主机角色。
- 实机：每一轮对比，不只最好/最差。
- 排查：怀疑过什么、为何否定——不只最终答案。

### 3. 完整数据支撑

- 至少一张全天/多轮总表。
- 数字写在文内；矛盾写出并解释。
- 没有数据就写「待补」+ 补什么、从哪拿——**禁止无依据定性结论**。

### 4. 可靠经验

- 标注：已验证 / 待验证 / 已推翻。
- 可复用方法与无效尝试分开写。
- 区分首因与放大因素。

### 5. 可信结论

- 独立「完整结论」节：判断 + **文内依据** + 置信度。
- O→H→V→C 链未闭合则标中/低置信度。
- **主动写误判**及纠正依据。

## 取材清单

1. 本机 `agent-transcripts/*.jsonl`
2. 本机 terminals（含 ssh 输出）——**把关键输出贴进经验文**
3. 实际改动机器上的 `git log` / `git diff`——**把关键 hunk 贴进经验文**
4. 远程测试/日志（角色主机，见 `remote-ssh-dev` → remote-materials.md）——**摘录贴进经验文**
5. 用户补充的目视观察、截图说明（关键数字/现象写入正文）

## 保存路径

| 文件 | 远端暂存 | 本机权威 |
|------|----------|----------|
| 长文经验总结 | `<项目根>/.cursor/工作存档/知识库/每日经验/YYYY-MM-DD-<主题>经验总结.md` | `D:\Documents\知识库\每日经验\` |
| 日索引 | `.../知识库/每日经验/YYYYMMDD.md` | 同上 |
| 日报 | `.../工作汇报/日报/YYYY-MM-DD-<主题>日报.md` | `D:\Documents\工作汇报\日报\` |

Remote-SSH 写完远端后，本机执行 `pull-reports-to-local.ps1`（见 `work-reporting-pipeline`）。

**不产出**：周报、每周知识库汇总（流程已取消）。

## 交付前自检

**离线自包含**：只读本篇能否还原判断与关键复现步骤？不能则补嵌入。

- [ ] 无「仅路径无摘录」支撑结论的句子
- [ ] 关键改动有 diff/前后片段；关键日志有原文；关键命令有期望输出
- [ ] 多轮总表在文内；数字有出处；矛盾已解释
- [ ] 可复用步骤 + 误判已写
- [ ] 完整结论节：每条有文内依据 + 置信度
- [ ] 至少一条完整 O→H→V→C
- [ ] 短索引仅入口；篇幅明显长于日报
- [ ] 隐私：无真实 IP/凭据/串号（占位符即可）

## 方法来源（借鉴，非教条）

- Evergreen notes（Andy Matuschak）：写给未来的自己；笔记须自立可读。
- 实验/工程笔记本：目的–环境–步骤–结果–验证；关键 provenance 写入记录本身。
- JetBrains / labcoat 类实践：结果旁附 **commit + patch/diff**，避免「只有指标没有改动」。
- ADR：重要选择写清 Context / Decision / Consequences / 弃选理由。

以上落到本仓库的可执行规则只有一条：**路径是附录，嵌入是正文。**

# 每日经验知识库

**读者是自己，不是领导。** 与日报不可混写、不可互相替代。

日报：给领导，一页为佳，结论为主。  
知识库：给自己，**离线自包含**——三个月后只翻本日长文，仍能还原完整知识链路。

写法硬标准与长文模板见 skill `daily-report` → [experience-summary-guide.md](../daily-report/experience-summary-guide.md)。  
本 skill：结构化章节 + **嵌入规范**；复杂主题须 **长文 + `YYYYMMDD.md` 短索引**。  
**不写周报 / 周汇总。**

## 核心原则（必须遵守）

1. **离线自包含（零号门禁）**：断网、不打开其他文件、不 SSH，只读本篇须能重建现象→假设→验证→改动→数据→结论。路径只做附录。
2. **嵌入优先于引用**：日志摘录、diff hunk、命令+期望输出、指标表写进正文；禁止仅「见 xxx 路径」。
3. **结论必有据**：每条判断旁注证据类型——`[日志摘录]` `[指标表]` `[代码diff]` `[命令输出]` `[对话/操作]` `[用户口述]`。
4. **数据不编造**：没有的数字写「待补充」+ 补什么、从哪拿。
5. **逻辑链完整**：O→H→V→C，缺环标「未验证」。
6. **对比才有说服力**：改前/改后、轮次间用表或并列呈现。
7. **失败同等重要**：失败轮、误判与纠正，写清差异变量。
8. **长文不可替代**：短索引不得省略推理链、全轮次表与完整结论节。

## 收集材料（必须主动执行）

遵循 `remote-ssh-dev` → `remote-materials.md`：

1. **本机**：transcripts、terminals（含 ssh 输出）→ **把关键输出贴进长文**
2. **远端**（当日用过的 Host）：`git diff`、日志 tail、测试指标 → **把关键 hunk/摘录贴进长文**
3. 用户粘贴的远端日志、实机表 → 转入正文表/代码块
4. 若已有日报：对齐主题，但经验文不得缩成日报加长版

证据标注：`[远程] 主机角色=… | 路径占位符=… | 时间=…`（路径附属；正文须已有摘录）。指标表含**主机**列。

## 输出结构

长文：`D:\Documents\知识库\每日经验\YYYY-MM-DD-<主题>经验总结.md`  
短索引：`YYYYMMDD.md`

## 与日报的关系

| | 日报 | 知识库（写给自己） |
|---|------|-------------------|
| 读者 | 领导 | 自己（离线） |
| 证据 | 代表数字 | **嵌入摘录 + 全轮次表** |
| 代码 | 不写 | **diff/前后片段** |
| 产出 | 单文件 | **长文 + 短索引** |
| 周期 | 日 | **仅日**（无周报） |

## 保存（本机为准）

| 文件 | 本机终稿 | 远端暂存 |
|------|----------|----------|
| 经验长文 | `D:\Documents\知识库\每日经验\YYYY-MM-DD-<主题>经验总结.md` | `<项目根>/.cursor/工作存档/知识库/每日经验/` |
| 日索引 | `D:\Documents\知识库\每日经验\YYYYMMDD.md` | 同上 |
| 索引表 | `D:\Documents\知识库\索引\每日清单.md` | `<项目根>/.cursor/工作存档/知识库/索引/每日清单.md` |

写完执行 `pull-reports-to-local.ps1`；确认本机文件存在。

## 交付前自检

- [ ] **离线自包含**：不打开外链/外文件也能还原判断
- [ ] 无「仅路径」支撑结论；关键 diff/日志/命令已嵌入
- [ ] 推理链无跳步；参数有改前改后；误判已写
- [ ] 无编造数据；不足标「待补充」
- [ ] 篇幅明显长于日报；有完整结论节
- [ ] 长文 + 短索引均已更新；本机文件已存在
- [ ] 无真实 IP/凭据（privacy-github）
